# 自動決済管理システム

## 1. プロジェクトの背景と目的
### 1.1. 現状の課題
本ゼミナール内で運営している「ゼミカフェ」は、完全セルフサービスかつ現金決済を中心とした小規模運用を行っていますが、以下の運用課題（コスト・手間）が発生していました。
* **アナログ管理の限界:** 10杯先払いサービスにおいて、紙に「正の字」を手書きして残数を管理しており、用紙の印刷やペンの記入といった物理的な手間が生じている。
* **売上・在庫データの不透明性:** 現金決済が主であるため、日々の売上集計やコーヒー豆・フィルターの在庫状況がリアルタイムに把握できず、手動での確認が必要である。
* **決済インフラの運用コスト:** PayPay決済を導入しているが、個人向けアカウントのQRコードは有効期限があるため、期限が切れるたびに紙の再印刷・貼り替え作業が発生する。

### 1.2. 目的
本プロジェクトでは、**「利用者の操作手間（UXの維持・向上）」**と**「ライトユーザーの心理的ハードルの低下」**を最優先に考慮しつつ、現場のエッジ端末（Raspberry Pi）とインターネット上のクラウドサーバーを連携させることで、**「決済・在庫管理の完全自動化」**および**「カフェ空間のモダンな演出」**を両立したWebシステムを構築します。

---

## 2. ターゲットユーザーとペルソナ
本システムは、利用頻度や決済手段に応じて異なるアプローチを提供します。

1. **ライト層（都度払いユーザー）**
   * **特徴:** たまにコーヒーを1杯だけ、現金またはPayPayで購入する学生・教職員。
   * **要件:** アプリのインストールや会員登録などの事前準備を一切させず、現行のアナログ決済と同等以上の手軽さで利用できること。
2. **ヘビー層（10杯先払いユーザー）**
   * **特徴:** 日常的にゼミカフェを利用し、事前に10杯分の代金を支払うゼミ生。
   * **要件:** 紙とペンを使わず、一瞬で「本人識別」と「残数カウントダウン」が完結すること。
3. **管理者（運営メンバー）**
   * **特徴:** カフェの在庫や売上を管理するメンバー。
   * **要件:** 自宅や外出先からでも、スマホやPCのブラウザ経由で最新の経営状況（売上・在庫）を一目で把握できること。

## 3. システムアーキテクチャ
実務レベルのWeb系企業へのアピールを見据え、ラズパイ内に処理を閉じ込めない**「クラウド・エッジ分離型アーキテクチャ」**を採用しています。

```text
[ 現場：エッジ端末 (Raspberry Pi) ]
 ├── 入力デバイス
 │    ├── M5Stick (コインセレクターからのパルス検知・送信)
 │    └── SONY PaSoRi RC-S380 (学生証 FeliCa/IDm読み取り)
 ├── 出力・表示
 │    └── ディスプレイ（キオスクモードWeb画面：WebSocketによるリアルタイム同期）
 └── マウス (PayPay決済時の自己申告UI用)
        │
        ▼ (インターネット越しにHTTP通信 / WebSocket通信)
        │
[ クラウド側：Webサーバー & データベース ]
 ├── バックエンドAPI (Python: FastAPI / Flask)
 ├── データベース (SQLite / PostgreSQL)
 └── 管理者用ダッシュボード画面 (HTML/CSS/JavaScript)
```

## 4. 学籍番号抽出の仕様について
特定サービスコード（`0x1A8B`）への直接アクセスは、`nfcpy` ライブラリの `ServiceCode` 仕様に依存する内部エラーや通信タイムアウトのリスクがあるため採用していません。

`tag.dump()` で取得した全体テキストから正規表現（`[A-Z]{2}\d{5}`）で抽出する方式を採用することで、通信の安定性と将来のカードフォーマット変更への柔軟性を確保しています。

## 5. コインセレクター制御におけるマイコン（M5Stick）の分離採用について
本システムでは、コインセレクターからの入力をRaspberry Piへ直接接続するのではなく、**M5Stick（マイコン）を経由して連携する分散構成**を採用しています。このアーキテクチャには以下の2つの重要な技術的根拠があります。

1. **リアルタイム性の担保（パルス取りこぼしの防止）**
   Raspberry Piは汎用OS（Linux）上で動作している性質上、裏で動くOSのタスク処理の影響を受けます。そのため、コインセレクターからミリ秒単位で高速入力される硬貨検知パルスに遅延が生じ、入金信号を見逃すリスクが高くなります。これをリアルタイム処理に優れたマイコン（M5Stick）に委譲することで、確実な信号検知を担保しています。

2. **シビアなタイミング制御の実現（無効硬貨の返却処理）**
   コインセレクターからのパルス出力自体は3.3VでありRaspberry PiのGPIOでも直接受電可能ですが、運用上「無効な硬貨を検知して即座に返却（リジェクト）する」ための制御信号（Disable信号など）をコインセレクター側へ送る必要があります。この信号送信は非常にシビアなタイミングが要求され、OSが介在するRaspberry Piでは正確な制御が困難です。そのため、ハードウェアレベルで正確なタイミング制御が可能なM5Stickを間に挟む設計としています。
